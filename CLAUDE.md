# Surge

## Project Context
Surge is a high-performance 2D/3D, mobile-first game engine inspired by Supercell's Titan engine. It is built to stay within the thermal limits, battery budget and memory bounds of mobile devices. It also runs fully on desktop, where it scales up (heavy Cascaded Shadow Maps, PBR, anti-aliasing, more lights, full render scale, etc.).

**Every change must respect the mobile budget first.** Desktop-only features must be optional/scalable and must never raise the cost of the mobile path. Prefer fewer draw calls, fewer render passes, fewer allocations, tile-friendly (load/store-op aware) rendering, and no per-frame heap churn.

- Platforms: **Windows** (development platform + runtime) and **Android arm64** (runtime). The Editor is Windows-only. iOS/Metal is planned; Linux/macOS desktop are intentionally unsupported (`Defines.hpp` `#error`s on them).
- Graphics API: **Vulkan 1.1** only (via volk). No DX12, ever. Android minSdk 29 is required for Vulkan 1.1.
- Note: `README.md` is partially outdated (C++ scripting/reflection serialization notes, dependency list). Trust the code.

## Repository Layout
- `Engine/` — `Surge` static library
  - `Source/Surge/` — engine modules: `Core`, `ECS`, `Graphics`, `Physics`, `Audio`, `ScriptEngine`, `Asset`, `Platform/{Windows,Android}`, `Utility`
  - `Source/SurgeReflect/` — in-house reflection (enum↔string, registry), `Source/SurgeMath/` — AABB/`Frustum`/math helpers, `Source/Surge/Core/Raptor/` — Rapt0R, the in-house binary serialization library (own style and README)
  - `Assets/Shaders/*.glsl` — engine shaders (cooked to `Assets/Shaders/Cooked/*.rSHADER`, tracked in git); `Assets/Internal/<ASSET_TYPE>/` — cooked binary assets; `Assets/AssetRegistry.surge` (text registry, Editor only; exports ship `Internal/Registry.rREG`)
  - `Vendor/` — vendored third-party code (glm, entt, ImGui/ImGuizmo, JoltPhysics, lua + sol2, miniaudio, basisu, SPIRV-Cross + shaderc (Editor only), volk, VMA, Vulkan-Headers, Optick, json). **Do not modify vendor code** unless explicitly asked.
- `Editor/` — Windows-only editor executable (ImGui panels, asset importer/cookers, Android export). Editor-only vendors (stb, cgltf, meshoptimizer) live in `Editor/Vendor`; `Editor/Tools/` holds `basisu.exe`, `msdf-atlas-gen.exe`, `rcedit-x64.exe`.
- `Player/` — runtime executable (`WindowsMain.cpp` / `AndroidMain.cpp` + shared `Player` client).
- `Android/` — Gradle project; `app/src/main/cpp/CMakeLists.txt` builds engine + player as `libSurgePlayer.so`.
- `Scripts/` — `WindowsGenProjects.bat`, `CMakeUtils.cmake`.
- `imgui.ini` (repo root) is tracked but rewritten by every Editor run: never edit, stage or report changes to it.

## Building
- **Windows**: `Scripts/WindowsGenProjects.bat` → checks CMake 3.20+ and Visual Studio (C++ workload + Clang tools, via vswhere), offers to drop a `build/` cache made by another VS install, then generates a VS solution in `build/` (`Surge.slnx`, ClangCL toolset). No prompts with `/y` or when `CI` is set; failures exit 1. All `Scripts/*.bat` share the same helpers/colors (amber, errors red, `NO_COLOR` for plain). Build in VS or `msbuild build/Surge.slnx -p:Configuration=Release`. Start project: `Editor` or `Player`. Working directory is the repo root (assets are loaded from `Engine/Assets` relative to it).
- **Android**: `Scripts/AndroidSetup.bat` installs the toolchain without Android Studio (Temurin JDK 17, SDK cmdline-tools, platform/build-tools, NDK and CMake versions parsed from `Android/app/build.gradle`), sets user `JAVA_HOME`/`ANDROID_HOME`/`PATH` and writes `Android/local.properties`; re-runnable, confirms every download/change (`/y` for unattended). `Scripts/AndroidClean.bat` undoes it (SDK/NDK, JDK, `~/.gradle`, `~/.android`, user env vars/PATH, repo build output), asking per part, only deleting folders that carry the expected markers. Then open `Android/` in Android Studio, or `Android/gradlew assembleDebug`. NDK `27.3.13750724`, arm64-v8a only, `c++_static`. The Editor's Export Panel drives Gradle with `-PsurgeAppName/-PsurgeApplicationId/-PsurgeVersionName/-PsurgeVersionCode/-PsurgeMinSdk/...`; signing secrets come only from `SURGE_KEYSTORE_*` env vars. Swappy (Android Frame Pacing) is pulled by Gradle and extracted as a plain static library (`extractSwappy` task), not through Prefab: its package also ships a `c++_shared` module that Prefab would reject.
- CI: `.github/workflows/WindowsCI.yml` (Windows Release build only). There is no test suite.
- Configs: `Debug`/`RelWithDebInfo`/`MinSizeRel` define `SURGE_DEBUG`; `Release` defines `SURGE_RELEASE`. Platform macros: `SURGE_PLATFORM_WINDOWS` / `SURGE_PLATFORM_ANDROID`.

### Build gotchas
- Sources are collected with `GLOB_RECURSE` — **re-run CMake after adding/removing files**.
- The Android build does **not** use `Engine/CMakeLists.txt`; it has its own source glob, include dirs, defines and vendor library targets. When adding a vendor lib, include dir, or compile define, update **both** `Engine/CMakeLists.txt` and `Android/app/src/main/cpp/CMakeLists.txt`. Anything under `Platform/Windows/` is excluded on Android automatically.
- Shaders are compiled **only by the Editor** (`Editor/Source/Shader/ShaderCompiler`, shaderc + SPIRV-Cross; the engine, Player and Android link neither, and exports ship no `shaderc_shared.dll`). Every platform loads the cooked `Engine/Assets/Shaders/Cooked/<Name>.rSHADER`, so open the Editor after editing a shader and commit the regenerated `.rSHADER` (a Windows Debug Player warns when a cooked shader is stale). The `Surge` post-build step copies `Engine/Assets/` into `Android/app/src/main/assets/`, Gradle's `ignoreAssetsPattern` keeps `*.glsl`/`*.glsli` out of the APK.
- Compiled with `/GR-` (**no RTTI**: no `dynamic_cast`/`typeid`), `/fp:fast`, `/W4`, C++20. Keep code warning-free (the MSVC toolset adds `/WX`); Android builds with `-Wall -Wextra`.
- Optick profiling is Windows-only; profiling macros compile to nothing on Android.

## Architecture
- **Core** (`Core/Core.cpp`): `Core::Engine` owns every subsystem in `Subsystem<T>` members declared in dependency order (Window → Renderer → Physics → AudioEngine → Diagnostics → ScriptEngine → AssetManager): `Initialize` creates them top to bottom, deleting the engine (`Core::Shutdown`, after the Client) shuts them down bottom to top, so the order lives in that declaration (the AssetManager goes first: its scenes/scripts hold Lua refs and GPU resources). `Core::Run()` loop is FrameCapper begin → Clock → `InputState::BeginFrame` → Window → Physics (fixed step) → `Client::OnUpdate()` → frame-end callbacks → `FrameCapper`. Minimized windows suspend the loop. `Core::GetRenderer()`, `Core::GetAssetManager()`, etc. forward to the engine (null before `Initialize`/after `Shutdown`); the game time scale lives in the `Clock`. Apps derive from `Surge::Client` (`Editor`, `Player`).
- **Layering**: `Core::Get*` is for the layers above the engine (Client, Editor, Player, Lua bindings, Renderer, Physics, UI, Platform). RHI, RenderGraph, HighLevel, Asset and ECS never include `Core.hpp` (no header does, so they cannot call `Core::`) and get what they use handed in: passes read `RenderPass::mContext` (`RenderGraphContext`: RHI, ShaderManager, text sampler, window size, ImGui flag, `DeferToFrameEnd`, filled by `Renderer::MakeGraphContext`), asset formats get an `AssetContext` (AssetManager, Renderer, SceneContext; cooked readers that create assets take it or an `AssetManager&`), `Texture2D/Font/Material::Create(Renderer&, ...)`, `Mesh::Create(Renderer&, AssetManager&, ...)`, and every `Scene` its `SceneContext` (`Scene::Create(name, Core::GetSceneContext())`, `Scene::GetContext()`).
- **Diagnostics** (`Core/Diagnostics`, `Core::GetDiagnostics()`): every runtime measurement lives here, consumers (overlay, Lua, the Editor's Renderer panel and title bar) only read it. Created after the Renderer, `Core::Run` calls `EndFrame(frameCapper.GetElapsedMilliseconds())` last in the frame. It measures only while read: `GetTimings()`/`Request()` keep it running for 1 s and turn the RHI's GPU timestamps on (off again when idle, unless `SetGPUTimingEnabled` set them explicitly); idle, `EndFrame` is one branch. `FrameTimings` (0.5 s windows): frame time, CPU work (frame time minus `RHIStats::CPUWaitMilliseconds`, the fence/acquire/present waits the RHI times), GPU work + the full scope tree (`Scopes`, RHI pre-order) + `Groups` (depth 1 summed by name), thermal + process CPU load (1 Hz, `Platform::GetProcessCPUSeconds`); `FrameCounters` (draw calls, submissions, entities, memory, resolution, GPU/CPU names, CPU threads) and a 240 frame `FrameHistory`. Sources stay where they are (RHI timestamps/waits, `Renderer::GetLastFrameCounts`, `Platform::GetThermalStatus`). Meant to grow into crash reports/log dumps. `Core::SetFramePacing(false)` is the profiling switch (no Swappy, no frame cap: GPU timings at full clock; paced phones lower the GPU clock until the work fills the interval).
- **Frame-end work**: use `Core::AddFrameEndCallback`. Entity destruction is deferred until frame end (`Scene::DestroyEntity`; `DestroyEntityImmediate` only when truly required).
- **RHI** (`Graphics/RHI`): `GraphicsRHI` is a thin facade over `BackendRHI` (= `VulkanRHI`). Resources are referenced by generational handles (`ImageHandle`, `BufferHandle`, `PipelineHandle`, ...) stored in `HandlePool`s — never hold raw Vulkan objects outside `RHI/Vulkan/`. Pipeline/descriptor layouts and vertex attributes are generated from shader reflection (baked into the cooked shader). Compute: `CreateComputePipeline` + `CmdDispatch` (outside render passes), storage images via `ImageUsage::STORAGE` / `DescriptorType::STORAGE_TEXTURE`; check `SupportsCompute()` and prefer fragment paths on mobile (storage images defeat framebuffer compression on tilers). `RHISettings::FRAMES_IN_FLIGHT = 2` (mobile default); per-frame resources are arrays of that size.
  - **Uploads** (`VulkanUploader`): buffer/image initial data and uploads are recorded into a batched upload command buffer with recycled staging blocks and submitted right before the next frame submission (same queue, so ordering is guaranteed) — no one-time submit + `vkQueueWaitIdle`. Never add blocking uploads; the CPU only waits when in-flight staging exceeds its budget.
  - **Pipeline cache**: `VkPipelineCache` loaded from / saved to `Platform::GetPersistantStoragePath()` (`SurgeVkPipelineCache.bin`), header-validated against the current device; pass `rhi.GetPipelineCache()` when creating pipelines.
  - **Frame pacing** (`VulkanFramePacing`): Swappy on Android presents on vsync at a target rate (keeps 90/120 Hz phones from rendering at 120 fps; auto swap interval drops a device that misses it to the next steady rate, e.g. 30 on 60 Hz, instead of 60/30 judder); no-op on Windows, where `FrameCapper` limits the rate.
  - **Pre-rotation** (`VulkanSwapchain::SelectPreTransform`): the swapchain takes the display's `currentTransform` (landscape game on a portrait phone: ROTATE_90, images 720x1600), so the compositor scans it out instead of rotating it on the GPU every frame. The window size stays in the window's orientation; every pass drawing into the swapchain (PostProcess, UIOverlay) rotates its output by `GraphicsRHI::GetSurfaceRotation()` quarter turns. A suboptimal present re-checks the transform (sensor flips).
  - **GPU timing** (`VulkanGPUTimer`): timestamp queries (one range per frame slot, BOTTOM_OF_PIPE) around nested named scopes, `GraphicsRHI::CmdBeginGPUScope/CmdEndGPUScope`; read without blocking after the slot's fence, so `GetGPUTimings()` is FRAMES_IN_FLIGHT frames old. `RenderGraph::Execute` times every group, and its passes only where that is meaningful (self managed groups, or `SupportsGPUTimingInRenderPass()`: false on Mali/Adreno/PowerVR, tilers run a whole render pass per tile); the Renderer wraps each view and the main graph. Before the swapchain group, `CmdWaitForSwapchainImage` (only while timing) isolates the GPU's wait for the acquired image behind a barrier in a wait scope: `Collect` leaves wait scopes out of `Scopes`, takes their time off the parents and reports it as `GPUTimings::DisplayWaitMilliseconds` (Diagnostics `GPUDisplayWaitMs`), so idle vsync time never reads as work. Runtime switch `SetGPUTimingEnabled` (on by default only with ImGui, i.e. the Editor), `RHISettings::GPU_TIMING` compiles it out.
- **Render graph** (`Graphics/RenderGraph`): passes derive from `RenderPass` (`Setup/Prepare/Execute/Resize/OnImGuiRender/Shutdown`, optional `HasWork`), belong to a `PassGroup` (SHADOW, MAIN_SCENE, AMBIENT_OCCLUSION, BLOOM, POST_PROCESS, UI_OVERLAY, SWAPCHAIN). `Prepare` runs for every enabled pass before any render pass begins — culling, instance/uniform uploads, descriptor updates and framebuffer changes go there, never inside `Execute`. Groups whose passes all report `HasWork() == false` are skipped entirely (no begin/clear/store). AO and Bloom (self managed, so never skipped by the graph) check `FrameBlackboard::RunsAO()/RunsBloom()` instead: no 3D draws after culling (`HasSceneGeometry`, set in `GeometryPass::Prepare`) / an empty main pass skips them, and PostProcess composites with the same checks. Groups with `ManagesOwnExecution` (Shadow, AO, Bloom) begin their own render passes and must insert their own internal layout transitions, and declare `mImageReads`/`mImageWrites`; `RenderGraph::Compile()` sorts passes, derives barriers and load/store ops. Shared per-frame data and settings live in `FrameBlackboard`. A passs `OnImGuiRender` only shows its stats (compact, `SeparatorText` title, nothing when it has none); settings UI belongs to the `RendererSettingsComponent` Inspector (`Panels/RendererSettingsInspector`).
- **Renderer** (`Graphics/Renderer`): gameplay/scene code submits CPU-side commands (`SubmitMesh`, `SubmitQuad`, `SubmitText`, `SubmitLight`, ...) into blackboard lists; passes consume them. Lists are cleared each frame.
  - `GeometryPass::Prepare` frustum-culls every submitted submesh (`SurgeMath/Frustum.hpp`, per-submesh AABBs), sorts by material/mesh and merges identical (material, mesh, submesh) runs into one instanced draw; per-instance transforms live in a per-frame storage buffer indexed by `gl_InstanceIndex` (`Renderer3D.glsl`). Lights are culled the same way and capped by `FrameBlackboard::Lighting.MaxLights` (8 on Android, 64 on desktop; shader array size `GeometryPass::MAX_LIGHTS`). `ShadowPass` (directional CSM) renders every cascade into one D16 atlas in a single render pass (viewport per cascade, `GraphicsRHI::CmdSetViewport`), cascades only cover `ShadowSettings::Distance`, the near plane is fitted to the casters (+ vertex shader pancaking), receivers use normal offset + tent PCF (`ShadowSettings::Quality` presets) and derive every cascade from one light space varying (scale + offset); the atlas keeps its handle when resized and bumps `FrameBlackboard::ShadowAtlasVersion` so `GeometryPass` rewrites its set 2.
  - **Render settings** (`RenderGraph/RenderSettings.hpp`): every settings struct (Shadow/AO/Bloom/PostProcess/Lighting/Particle/Animation + render scale) aggregated in `RenderSettings`, with `Default(RenderProfile)` per platform. Scenes save them in a `RendererSettingsComponent` (new scenes put it on the Environment entity) holding a `Desktop` and a `Mobile` profile; Android uses MOBILE, Windows DESKTOP (`PLATFORM_RENDER_PROFILE`), the Editor previews either one via `Renderer::SetRenderProfile` (the Inspector's profile switch). `Scene::UpdateRendering` submits the first active component's profile (or `RenderSettings::GetDefault`) every frame; `Renderer::SubmitRenderSettings` writes the main blackboard only when it differs from the last applied copy (views copy from there). `RenderSettings::VisitSavedFields` lists every saved field once: it drives the JSON, the cooked SceneBinary (`SerializedFieldKind::RENDER_SETTINGS`) and the schema hash, so add new fields there (debug toggles stay out). Lua: `entity.RendererSettingsC.Desktop/Mobile/GetCurrentProfile()`, nested settings by reference, `ApplyQualityPreset` to change a quality.
  - Render scale (`Renderer::SetRenderScale`, `RenderScaleSettings`): the 3D scene (main pass, AO, bloom) renders at 0.5–1.0x of the output, UI and post-processing stay at full resolution. Default 0.8 on Android, 1.0 on desktop.
  - **Render views** (`Renderer::CreateView` & co, Editor-only): offscreen copies of the scene passes (own `RenderGraph`, targets, FrameUBOs) with their own camera/size. `EndFrame` copies the frame's submissions + settings into each requested view, executes it before the main graph and transitions its `FinalImage` to SAMPLED for ImGui. Submissions after `BeginEditorOverlay()` (gizmo lines, axes) only reach views with `EditorOverlay`. The Editor disables the main graph's scene groups (`SetMainSceneEnabled(false)`): it only presents ImGui. Views render only on frames after `RequestViewRender` (ImGui runs after the views); resizes/destruction land at frame end. The Player never creates views. `RenderViewDesc::Isolated` views (Particle Editor preview) get no scene submissions: only what `SubmitParticles(..., viewID)` sends them, cleared after each execution.
- **Particles** (`Graphics/Particles`): `ParticleEffect` assets (`.spfx` JSON source, cooked to `ParticleEffectBinary`) hold up to 16 emitters of plain-data modules (curves/gradients baked to 64 entry LUTs). `ParticleSystemComponent` owns the live state (`ParticleRuntime`: one SoA pool per emitter, allocated once; a copy starts empty, so Play mode/duplicates never share particles). `Scene::UpdateParticles` runs right after `Renderer::BeginFrame` (Player: culled with `FrameBlackboard::CameraFrustum`, Editor: no culling) and packs 32 byte `ParticleRecord`s through `Renderer::SubmitParticles`; the Renderer stays ECS-agnostic. `ParticlePass` draws them inside the main pass after `Renderer2DPass` (one premultiplied pipeline for alpha + additive, vertex pulling from a per-frame SSBO, emitters sorted back to front, optional per-particle radix sort, one draw per texture run). Budget: `FrameBlackboard::Particles` (8k live on Android, 128k desktop). Effect edits call `ParticleEffect::MarkChanged(layoutChanged)`: parameter edits keep running instances, layout changes restart them.
- **Animation** (`Graphics/Animation`): glTF skins + clips are cooked into the `Mesh` (`MeshSpecification::Skeleton_/Skin/Clips`, `MeshBinary` animation section): the skeleton holds every needed node parents-first, vertices index a palette (skin joint + inverse bind, or a node rigid geometry hangs from, so animated props are one-joint skins), 4 u8 joints + 4 unorm8 weights per vertex (`SkinnedVertex`, 64 bytes). Clips are resampled to 30 Hz by `MeshCooker` (sampling = two reads + lerp/nlerp). `AnimatorComponent` (+ up to 4 `ClipSource` meshes retargeted by node name) owns its `AnimatorRuntime` (copy starts empty); `Scene::UpdateAnimation` runs right after `UpdateParticles` (Player culls with last frame's pose bounds), the mesh loop submits `Renderer::SubmitSkinnedMesh` (palette appended to `FrameBlackboard::SkinMatrices`, budget `Animation.MaxSkinMatrices`). Skinned meshes always draw skinned (`SubmitMesh` falls back to the rest palette). `Renderer::UploadSkinMatrices` uploads one SSBO per graph before the passes prepare (`SkinBufferVersion` -> passes rewrite descriptors); Geometry/Shadow passes keep a second instanced list drawn with `Renderer3DSkinned`/`ShadowSkinned.glsl` (`Include/Skinning.glsli`; Renderer3D's stages live in `Include/Renderer3DFragment/Vertex.glsli`). Lua: `entity.AnimatorC:Play(name, fade)` & co (`ScriptEngine/Bindings/AnimationBindings.cpp`).
- **Shaders**: one `.glsl` file per program with stage markers `//SURGE:[Shader: Vertex]` / `//SURGE:[Shader: Fragment]` / `//SURGE:[Shader: Compute]` (compute-only files are loaded with `ShaderManager::Load(name, ShaderType::COMPUTE)`). Shared code lives in `Shaders/Include/*.glsli`, pulled in with `#include` (+ `#extension GL_GOOGLE_include_directive : require`), resolved at compile time. `ShaderManager::Load` calls the compile hook (`ShaderManager::SetCompileHook`, installed by the Editor before `Core::Initialize`), which recompiles when the cooked file is missing, from an older `ShaderBinary::VERSION` (bump it when the format or compile options change) or the source/an include changed (FNV hash of the files, stored with the include list). `Shader::Load` only reads `ShaderBinary`: SPIR-V compiled with `-O` (performance) + `ShaderReflectionData` reflected from an unoptimized compile, since the optimizer strips names. UBO structs mirrored in C++ must keep std140 layout and the `static_assert(sizeof(X) % 16 == 0)` checks.
- **ECS** (`ECS/`): EnTT-backed `Scene` (which is itself an `Asset`) + `Entity` wrapper. Components in `ECS/Components/`. Saved components are listed once in `SERIALIZABLE_COMPONENTS` (`Asset/Format/Scene/SerializableComponents.hpp`), shared by the Editor's JSON source (`SceneSourceIO::ToJson/FromJson`, plus `EntityToJson/EntityFromJson` snapshots for the Editor's undo and copy/paste) and the cooked `SceneBinary` (reflection driven; a schema hash of names + field kinds re-cooks every scene when a component changes).
- **Assets** (`Asset/`, AssetManager v2): the engine only reads cooked binary files, the Editor owns every source format and every write.
  - **Engine** `AssetManager`: `Load<T>/GetLoaded<T>/Unload/UnloadUnreferenced/GetIDFromPath/GetBuiltin` with stable `AssetID` (UUID); loading is synchronous. Never call `Load<T>` every frame. It reads `Internal/<TYPE>/<id>.r<TYPE>`, checks its 32-byte `CookedHeader` (`Asset/Format/CookedFile.hpp`: magic, type vs registry, format version, payload size) and hands the payload to the type's `AssetFormat` (`Asset/Format/<Type>/<Type>Format`: `Read`, plus `Write` of a live asset for authored types, `CreateBuiltin` for `Engine://` meshes). Each format's payload layout lives once, read + write, in its `<Type>Binary` namespace; cookers write the same payload from source data. Exported games read `Internal/Registry.rREG` (`RegistryBinary`) at `Initialize` and trust it (no per-asset `Exists`). Editor-facing in-memory API, no disk writes: `Register/Unregister/SetPath/Adopt/Invalidate/Clear/SetCookHook`. `GetIDFromPath` is a hash lookup (exact, case sensitive like the APK; Windows warns on case-only misses). A failed load marks the asset MISSING; the Player never retries it, the Editor always does. The Player calls `UnloadUnreferenced()` after a scene change (frees assets with Ref count 1), so anything that must outlive that holds a `Ref`, Lua included (sol `Ref<T>` traits live in `ScriptEngine/Lua.hpp`).
  - **Editor** `AssetDatabase` (`Editor/Source/Asset/AssetDatabase`, `AssetDatabase::Get()`): the only code writing into a project's Assets folder. `OpenProject` (text registry -> `Register`), `Import/Create<T>/Save/SetPath/Unregister`, `SaveRegistry` (after each change) and `WriteCookedRegistry` (export), the cookers (`Asset/Cookers`, `Cook(const CookContext&)`) and freshness. `Save` means the same for every authored type: write the source (`Asset/SourceIO`: `SceneSourceIO`, `ParticleEffectSourceIO`, `UILayoutSourceIO`, `MaterialSourceWriter`, `ProjectSourceIO` for the `.surgeproj`), then the cooked file from memory with a fresh header. Mesh material overrides are source data in `<model>.import` (`ImportSettings`, JSON next to the source, also `Texture.ColorSpace`; `AssetFileOps` moves/copies/deletes it with its source), baked into the cooked mesh by `MeshCooker`: saving a mesh writes the `.import` and re-cooks. Source extensions (`AssetTypeFromExtension`) live in `Asset/AssetExtensions.hpp`.
  - **Freshness**: the cook hook (`AssetCookHook`, installed by `AssetDatabase::Initialize`) runs on `Load`: a cached asset costs one write-time check of its source + `.import`, a miss checks the header (`CookerVersion`, `FormatVersion`, `SourceModTime` = newest input write time; on a time mismatch the `InputHash`, FNV-1a of source + `.import` + cooker extras like a script's path, decides, and a match only rewrites the header time). A fresh clone doesn't re-cook. Textures go through basisu (UASTC KTX2), transcoded at load to ASTC/ETC2 on Android and BC7 on desktop (RGBA8 fallback). Cooked audio/scripts are the encoded file/bytecode as is (`CookedFile::TakePayload`).
  - Every binary format (cooked assets, registry, project, shaders, the pipeline cache header) reads and writes through Rapt0R (`Core/Raptor`, header-only, fused `Writer::Write`/`Reader::Read`, sticky errors checked once): `Asset/Format/BinarySerialization.hpp` adds `SURGE_RAPTOR_FIELDS(Type, v.A, v.B, ...)` (one field list for the `Rapt0RSerialize/Rapt0RDeserialize` pair, declared in the type's namespace before any Write/Read of it), `SURGE_RAPTOR_RAW(Type, Size)` (every raw-copied type) and `IsEnumInRange`. Readers are bounds checked and must fail cleanly on truncated/stale files, never rely on `SG_ASSERT`: validate counts/enums/indices after reading (`SetError(CORRUPT_DATA)`). A layout change bumps the format's `VERSION`.
  - Adding an asset type: `AssetType` + `sAssetTypeArray` + its string, an `AssetFormat` registered in `AssetManager`'s constructor (engine), a cooker registered in `AssetDatabase::Initialize`, an extension in `AssetExtensions.hpp`, and a SourceIO + a `Save` case if the Editor authors it. Nothing in export (it ships every registered cooked file).
- **Physics**: Jolt, fixed timestep (project `FixedRate`, 60 Hz default) with render interpolation (`GetInterpolatedPosition/Rotation`); use `Teleport` to snap. `PhysicsSettings` (gravity, rate, substeps, 16 named layers + symmetric collision matrix) live in the `.surgeproj` (`Project::Physics`, cooked into `Internal/Project.rPROJ` by the export), applied by `Physics::ApplySettings` on project open and by the Editor's Physics panel live. Jolt object layer = layer * 2 + moving bit (broad phase still static/moving); `RigidbodyComponent::Layer`, Lua `Physics.GetLayer/GetLayerMask`, `Raycast(..., layerMask)`. Convex/mesh collider shapes are built once per mesh (unscaled, `Physics::mMeshShapes`, keyed by mesh AssetID) and shared: each collider wraps it in a `RotatedTranslatedShape` (offset/rotation) + `ScaledShape`; only a scale Jolt rejects (non-uniform on a rotated collider) bakes its own shape. `Scene::OnRuntimeEnd` clears the cache.
- **Scripting** (`ScriptEngine/`): Lua 5.4 via sol2, one state for the app, scripts compiled to bytecode at cook time with `"@" + asset path` chunk names. Bindings in `ScriptEngine/Bindings/`; keep `ScriptEngine/Intellisense/SurgeAPI.lua` in sync when the Lua API changes (the Surge Lua VS Code extension, a separate repo next to this one (`../SurgeLuaExt`), ships it to the Lua language server: rebuild it after an API change; a binding taking an asset path or script/entity/widget/layer name also needs a `RULES` entry in its `Source/LuaCalls.js`). sol types must not leak into widely included headers (`ScriptEngine.hpp`/`ScriptAsset.hpp` stay sol-free, see `GetSOLState()`; `ScriptComponent.hpp` is the exception).
  - `ScriptComponent` holds a list of `ScriptEntry`s (multiple scripts per entity, own Active flag, Fields and `ScriptInstance` each); `UICanvasComponent` has one instance. Each instance runs in its own environment falling back to `_G`; `ScriptEngine::Instantiate` + `CallOn*` drive it. Callbacks get a cached entity object (`Self`), never allocate per call.
  - Frame order (`Scene::UpdateScripts`): physics fixed steps already ran in `Core::Run` and called `OnFixedUpdate` through `Physics::SetFixedStepCallback` -> contact events (`OnCollisionEnter/Exit`, `OnTriggerEnter/Exit`; the `ContactListener` counts sub-shape contacts per body pair) -> `OnEnable/OnDisable` flips + `OnUpdate` -> new scripts' `OnCreate` + `OnEnable` (all instantiated first, so `GetScript` works in `OnCreate`) -> UI canvases -> `OnLateUpdate`. Scripts are re-fetched by index after every Lua call (a callback may remove components); scripts added from Lua wait in `PendingScripts` until the next frame.
  - Lua APIs beyond the components: `Time.*` (script time + `Core::SetTimeScale`, which scales physics accumulation and script dt), `Scene.Load/FindEntity/CreateEntity` (`Scene.Load` -> frame-end `Client::ChangeRuntimeScene`: Player and Editor swap in a fresh copy of the scene asset, the Lua session survives), `Physics.Raycast`, `Particles.Play(path, position, rotation)` (one-shot: an entity with an AutoDestroy `ParticleSystemC`), `Storage.Save/Load/Has/Delete` (JSON files under `GetPersistantStoragePath()/<Project>/SaveData`, std::filesystem on purpose: Filesystem reads the APK on Android).
  - **Modules**: `require` only resolves script assets (custom `package.searchers`, no filesystem/C modules): `"Scripts.Game.State"` → `Assets/Scripts/Game/State.lua`, cached per canonical path, own environment, a module without return exports its globals. This replaces sharing state through `_G`. `ScriptEngine::ResetSession()` (Editor: Play start/stop) unloads modules and removes globals scripts added to `_G`; the Player never resets.
  - **Properties**: scripts declare `Properties = { ... }` (plain values or `Property.Float/Int/Bool/String/Vec2/Vec3/Vec4/Color/Entity/Asset/Enum/Array`, which return plain values at runtime; assets are saved by ID and handed to Lua as paths). The Editor extracts the schema (`Editor/Source/Scripting/ScriptFields`) by running the script with recording `Property.*` helpers; the runtime never does. Per-entity values are `ScriptFieldOverride`s saved sparsely in the scene (`"Fields"`) and written into `Properties` once before `OnCreate` (`ScriptEngine::SetFields`) — zero per-frame cost; keep it that way.
  - Sandboxed: `os` has only time/clock/date/difftime, no `io`/`debug`. Errors carry Lua tracebacks (default sol handler).
  - **Performance overlay** (`ScriptEngine/Builtin/PerformanceOverlay`): Ctrl+F3 (or a two finger triple tap: OEM three finger screenshot gestures cancel touches on many phones) cycles Off/Compact/Detailed in every app and build. Display only: an engine Lua script embedded in `PerformanceOverlay.cpp` (own environment, adds no globals, survives `ResetSession`) reading `Diagnostics.GetStats` and drawing UI widgets into `UI::Manager::SetDebugRoot` (above every canvas, never hit tested, kept across scene changes). `Core::OnEvent` routes the hotkey, `Core::Run` calls `PerformanceOverlay::Update` after `Client::OnUpdate`. Hidden it costs nothing (no Lua call, no draw, Diagnostics goes idle); shown: one Lua call a frame, the graph moves a write head (2 widget writes), text rebuilt at 4 Hz. The strip's CPU is `CPUWorkMs`, the frame time is the FPS and the Detailed info line. Keep the script under MSVC's ~16 KB literal limit.
  - **Lua Diagnostics** (`ScriptEngine/Bindings/DiagnosticsBindings`, thin forwarding only): `Diagnostics.GetStats(t)` (fills the caller's table from `FrameTimings` + `FrameCounters`), `SetFramePacing/IsFramePacingEnabled`, `ToggleOverlay/SetOverlay/GetOverlay/SetHotkeyEnabled/IsHotkeyEnabled`.
  - **Engine UI font**: `EngineFont::COOKED_PATH` (`Engine/Assets/Fonts/Cooked/EngineUI.sFONT`, committed), cooked from Roboto SemiCondensed Bold by `FontCooker::CookEngineFontIfOutdated` before `Core::Initialize` (stamp = content hash), shipped by `ExportUtils::CollectCookedContent`. `Renderer::GetEngineFont()` loads it lazily; UI text without a font (Lua without a font path, `UILayout` widgets without a Font asset via `LayoutResourceCache::GetFont`) uses it.
- **Audio**: miniaudio, played from memory: the `AudioEngine` never opens files (no VFS) and knows nothing about cooked formats. `CreateAudio(Ref<Audio>, streaming, spatialized)` returns a sound that holds the clip's `Ref`; streaming sounds decode the clip's bytes as they play, the others share s16 PCM decoded once per clip and registered with the resource manager (`~Audio` unregisters it). `Scene::UpdateAudio` rebuilds a source's sound when its clip is swapped. ImGui is tools/editor only (disabled in Player).
- **Input** (`Core/Input`): platform windows only emit events (keys, mouse, `Touch*Event` per pointer, `WindowLostFocusEvent`); `InputState` (fed from `Core::OnEvent`, frame bookkeeping in `Core::Run` before `Window::Update`) builds key/mouse edges, multi-touch (`Input::GetTouch`, phases BEGAN..ENDED/CANCELED, small stable IDs, left mouse = touch on desktop) and gamepads (XInput on Windows, joystick events on Android). Mouse events synthesized from touch carry `IsFromTouch()` so nothing handles a tap twice; the UI manager tracks one pressed widget per pointer. Android: primary touch still drives the emulated mouse/ImGui, hardware keys map to the same `Key` codes as Windows, Back = `Key::Escape` (+ app exit unless `Input::SetBackButtonExitsApp(false)`).
- **Game UI** (`Graphics/UISystem`): `UI::Widget` tree with a Unity-style rect transform (AnchorMin/Max, Pivot, Offset, Size; layout cached once per frame). `UI::Manager` holds one canvas per `UICanvasComponent` (keyed by entity UUID, `SortOrder`, `CanvasScaler`) plus an editor preview root. Layouts are `UILayout` assets (`.sui` JSON source, cooked to `UILayoutBinary` like scenes) authored in the Editor's **UI Editor** panel (WYSIWYG editing in the Viewport); Lua finds widgets with `entity.UICanvasC:FindWidget("Name")`, `SetUIRoot()` still works for code-built UI. Sprites and MSDF text share one shader/pipeline (`UI.glsl`, `UIOverlayPass`) and are drawn in `FrameBlackboard::UIDrawOrder` (hierarchy order).
  - Widgets: Panel, Image (SIMPLE/SLICED 9-slice/FILLED), Text (wrap/truncate), Button, ImageButton, ProgressBar, Toggle (checkbox/switch, radio groups), Slider, Joystick, Spinner, SafeArea, LayoutGroup, TabView (`UIWidgets.*`), ScrollView + recycling ListView (`UIScrollView.*`), Dropdown + Modal (`UIPopups.*`), InputField (`UIInputField.*`). Drawn parts use `UI::ImageStyle`/`DrawImage` (desc side: `ImagePartDesc` Background/Fill/Handle). Adding a widget type means touching `WidgetType`, `UILayout.cpp` (strings, `CreateDefault`, `Instantiate`), `UILayoutSourceIO` (Editor) + the `UILayoutFormat` field list, `UIBindings` (+ `ToTypedLuaObject`), `SurgeAPI.lua` and `UIEditorPanel::DrawWidgetSettings`/`DrawAddWidgetMenuItems`.
  - UI sprites are `UISpriteCmd` (pixel rect + UV rect + corner radius). Clipping is CPU side: `UIDrawItem::ClipIndex` -> `FrameBlackboard::UIClipRects`, `UIOverlayPass::PushQuad` shrinks quads/UVs (no scissor, batches intact). Rounded corners: radius in `TextureIndex` bits 8-23 of non-text quads, SDF in `UI.glsl` (rect size from UV derivatives).
  - Input: pointer presses/drags per pointer ID (`OnPointerDown/Drag/Up`, `WantsDrag`), a child press that turns into a drag is handed to the nearest ancestor with `CanTakeOverDrag` (scroll views). Overlays (`Manager::OpenOverlay`) draw above every canvas and are hit first, Back/Escape dismisses the top one (`Event::Handled` keeps Android Back from exiting). One focused widget gets keys/text; Android text goes through GameTextInput (`Platform::ShowSoftKeyboard/PollTextInputState`, UTF-16 <-> UTF-8 offsets), the canvas slides up over the soft keyboard. `UI::GetFrameInfo()` (time, dt, safe insets) is set by the Manager each frame; the Game view can simulate safe areas.
- **Resource lifetime**: RHI `Destroy*` calls are deferred until the GPU is done (works both during and between frames). Lua (sol) references must be released before `ScriptEngine::Shutdown()` closes the Lua state.

## Editor (`Editor/Source`)
- Panels derive from `IPanel` and are owned by `PanelManager` (`PanelCode` enum). `Editor` owns the custom title bar (`Panels/EditorTitleBar`: one row with logo, menus, project/scene breadcrumb, play controls, frame stats, console counters, drawn window buttons; not an `IPanel`, empty space drags the window through `Window::SetCaptionHeight`), the dockspace and the undo history (`History/`: edits are recorded while in edit mode, undo/redo applied at frame end).
- **Per-project settings** (`Settings/EditorSettings`): editor state (camera view, viewport/gizmo options, content browser state, frame cap) is saved to `<ProjectDir>/EditorSettings.json` and restored when the project is opened. Editor wide preferences (theme) are `EditorPreferences` in `<PersistentStorage>/EditorPreferences.json`, loaded before the first frame.
- **Status bar** (`StatusBar/EditorStatusBar`): footer under the dockspace showing the latest Console line (click → Console), timed `Notify()` messages and progress tasks (`SetTask(key, title, progress|INDETERMINATE, detail)` / `EndTask(key)`, thread-safe). Long-running editor work (export, thumbnail loading, ...) should report through it.
- **Viewports** (`Viewport/`): Unity-style `SceneViewport`s (own `EditorCamera`, tools, gizmos, ImGuizmo with a per-view ID, picking) and one `GameViewport` (scene's primary camera, aspect presets, in-game UI), Scene views any number (VIEW menu, closable tabs), each backed by a Renderer view. `ViewportManager` owns them: camera input goes to the hovered Scene view (kept while a button is held). The Game view is limited to one on purpose: the game has one screen, the UI is laid out once at its size (`Renderer::SetUIView`), only it takes UI input and hosts the UI Editor handles, and runtime cameras/scripts use its resolution; a second one would only show a stretched copy of that layout. Window IDs are `###SceneViewN`/`###GameView1` so imgui.ini docking follows the index; the open set is saved per project (`EditorSettings::Viewports`). The scene's render hook (`Editor::mSceneRenderHook`) sets the view cameras, then `BeginEditorOverlay()`, then editor debug geometry.
- **Gizmos** (`Gizmos/`): `SceneGizmos` draws component icons (procedural vector glyphs in `GizmoIcons`), camera frustums and light/audio ranges as an ImGui overlay in each Scene view (icons are clickable), and submits colliders to the renderer through the `editorDraw` hook of `Scene::Update(EditorCamera&, ...)`. 3D wires go through `GizmoCanvas` (near-plane clipped ImDrawList lines), emitter shapes/collision planes through `ParticleGizmos`, both shared with the Particle Editor preview (which also runs its own ImGuizmo, ID `PREVIEW_GIZMO_ID`, on the selected emitter's shape). Keep editor-only visualization out of `Engine/` so the Player and runtime scenes never pay for it. ImGuizmo (`Engine/Vendor/ImGui/ImGuizmo.*`) carries local `// SURGE:` styling changes (outlines, `OutlineThickness`/`InfoRounding`, `OUTLINE`/`INFO_BACKGROUND` colors).
- **Viewport selection** (`Picking/ScenePicker`): CPU ray casts on click (submesh AABB → triangles from `Mesh::GetVertices/GetIndices`, sprite quads, text blocks measured like `Renderer2DPass`), gizmo icons take priority. No ID buffer / GPU readback by design, keep it Editor-only.
- **Content Browser** (`Panels/ContentBrowserPanel`, `Asset/AssetFileOps`, `Asset/ThumbnailCache`): file operations keep the asset registry in sync; image thumbnails are decoded from source on a worker thread and uploaded a few per frame. Ctrl+Space opens it as a Unreal-style Content Drawer (`ToggleDrawer`: slides up over the editor, also with the tab closed; Esc, a click outside or a drag leaving it closes it, height saved as `ContentBrowserSettings::DrawerHeight`); tab and drawer share `DrawBody()`, only one draws it per frame.
- **Export** (`Export/`): `ExportManager` cooks on the main thread, then runs the platform exporter on a worker thread (`ExportSession` is the thread-safe shared state); Android export drives Gradle. Builds ship only `Assets/Internal/`: the cooked file of every registered asset, `Registry.rREG` and `Project.rPROJ` (written by `CollectCookedContent`; the Player loads both), + the cooked engine shaders (`ShaderCompiler::CookLoadedShaders` recompiles outdated ones first), collected on the main thread after cooking; an uncooked asset or a shader that fails to compile fails the export. Android: `AndroidToolchain::Detect` resolves the JDK/SDK/NDK/CMake/platform/adb/Gradle paths like gradlew.bat and AGP do (versions parsed from `build.gradle` + the wrapper; local.properties wins over `ANDROID_HOME`), shown in the panel's TOOLCHAIN section, and passes user env vars set after the Editor started to Gradle. A failed 'Install on device' offers REATTACH ADB & INSTALL (`AndroidDeviceInstaller`: own worker + session, restarts the adb server, waits for an authorized device, installs with `-s <serial>`). `AndroidLogcat` (Export panel 'Device log', auto-attached after a launch) streams the app's logcat into the Console under `[Device]>>`: SurgeEngine lines + W/E of its pid (followed via `Start proc`), plus its debuggerd tombstone with `libSurgePlayer.so` frames run through the NDK `llvm-symbolizer` against the newest unstripped lib in `Android/app/build/intermediates/cxx` (skipped on a BuildId mismatch).
- **Renderer panel** (`Panels/RendererPanel`): RHI tab shows the RHI metrics (GPU, memory, pools), Graph tab draws the selected graph with `RenderGraphVisualizer` (pass toggles apply to every viewport by default), Stats tab calls the selected graphs passes `OnImGuiRender`. Performance tab draws Diagnostics' numbers (no measuring of its own): the whole frame's GPU scopes (every view, then the main graph), with the GPU Timing switch (`Diagnostics::SetGPUTimingEnabled`): GPU/CPU work/hottest-scope cards colored against a target budget (30–120 Hz), a GPU work + CPU work + frame time graph (`FrameHistory`) with the budget line, a stacked per-group bar (fixed color per `PassGroup` name) and the scope tree. Shares are of the GPU work (sum of the top level scopes), not the command buffer, which includes the swapchain wait. `RenderGraphTarget` picks the graph (active Scene view by default; the main graph only presents ImGui in the Editor).
- **Console** (`Console/EditorConsole`): receives every `Log()` line through the logger sink, installed before `Core::Initialize`.
- **EditorUI** (`Utility/EditorUI`, namespace `EditorUI`): the Editor's only ImGui toolkit. Every color is an `EditorUI::Colors` entry, never a literal in a panel. Dark/Light theme (`EditorUI::SetTheme`, saved in `EditorPreferences`, switched from VIEW > Theme or the Project Browser, applied at frame end): the tone ramp `ToneNN` (NN% brightness in Dark, mirrored in Light), `Ink` (contrast color: hover tints, active glyphs), the roles (`Text`, `Selection`, ...) and status colors are runtime `inline` values, so read them at draw time, never into `constexpr`/static constants; brand, `Component`/`Asset`/`PassGroup`/`Gizmo` palettes and `Viewport` (drawn inside rendered scenes, dark in both themes) stay `constexpr`. Derive with `WithAlpha/Scale/Mix`, `ToU32` is constexpr. Reusable widgets/draw helpers go there instead of a file's anonymous namespace; `T*` functions are two column table rows (`BeginPropertyTable`, `TLabel`, `TDragFloat`, ..., `ScopedBoldValues` for Inspector style values).

## Coding Standards (C++20)
Follow the existing style of the engine exactly:
- Every file starts with `// Copyright (c) - SurgeTechnologies - All rights reserved`; headers use `#pragma once`. Files are `.hpp`/`.cpp`. Include paths are rooted at `Source/` (e.g. `#include "Surge/Core/Defines.hpp"`).
- Everything lives in `namespace Surge` (sub-namespaces like `Surge::Core`, `Surge::UI`), closed with `} // namespace Surge`.
- Allman braces, 4-space indentation.
- Naming: `PascalCase` types, functions and **public struct fields** (`Desc.Width`); `mMember` for private/protected members, `sStatic` for statics, `camelCase` locals/params; `UPPER_CASE` for enum values and constants; `SCREAMING_CASE` macros.
- `UUID`/`AssetID` to integer: always `.Get()`. `operator uint64_t()` is non-const, so `static_cast<uint64_t>` on a const UUID silently goes through `operator bool` and yields 1.
- Use engine aliases/utilities: `Ref<T>`/`Ref<T>::Create` (intrusive, for `RefCounted` types), `Scope<T>`/`CreateScope`, `Vector<T>`, `String`, `Uint`, `Byte`, `Path`, `UUID`.
- Logging: `Log<Severity::Info>("[System] message {}", arg)` (std::format syntax, prefix with the subsystem in brackets). Assertions: `SG_ASSERT(cond, "msg")` / `SG_ASSERT_INTERNAL` — compiled out in Release, so no side effects inside them.
- Profiling: `SURGE_PROFILE_FUNC()` in hot functions.
- Use `FORCEINLINE`, `NODISCARD`, `SURGE_DISABLE_COPY[_AND_MOVE]`, `MAKE_BIT_ENUM` from `Defines.hpp`.
- Platform-specific code goes in `Platform/<OS>/` or behind `SURGE_PLATFORM_*` guards.
- Performance: no allocations or `std::function`/virtual dispatch in tight per-object loops where avoidable; reserve vectors; keep hot data contiguous; avoid heavy headers in widely-included headers (forward-declare, as done for Jolt/sol).
- Keep comments sparse and purposeful, matching surrounding density. Author notes use `// (Rid)` / `// NOTE(Rid)` / `// TODO:`.
